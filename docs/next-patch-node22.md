# Patch Next.js and update the Docker runtime

Implemented on a review branch (not merged or deployed), based on clean `origin/main` at `b7bae9c`. No app behavior changes, dependency upgrades unrelated to this patch, demo profile, rate limits, hosting changes or deployment. Scope also includes one new image-verification job in `.github/workflows/ci.yml`. No local Docker installation is required. This is a prerequisite for, not approval of, a public demo.

## Change and rationale

- Lock `next` to **16.4.5**, the first stable 16.4 patch above the reported affected range ending at 16.4.4. Set the manifest to the exact string `"16.4.5"`, without a caret (currently `^16.3.8`), and lockfile (currently resolves 16.4.3), including only necessary framework transitive changes. Keep `next-auth` exactly `5.0.0-beta.32`; its published Next peer range `^14.0.0-0 || ^15.0.0 || ^16.0.0` accepts 16.4.5. No forced peer overrides. Keep `eslint-config-next` at its current resolution (16.3.8): no matching patch was necessary for the probe and lint passed.
- Reviewed the bundled installation/self-hosting guides and the [16.4.4](https://github.com/vercel/next.js/releases/tag/v16.4.4) and [16.4.5](https://github.com/vercel/next.js/releases/tag/v16.4.5) release notes. 16.4.4 backports fixes; 16.4.5 lists seven security fixes. No application migration is documented for this patch pair. [16.4.6 (Nov 9)](https://github.com/vercel/next.js/releases/tag/v16.4.6) also automatically compresses route-handler responses that were not already compressed. That behavior change is unnecessary for this security fix, so prefer the narrower 16.4.5 patch if it still passes the audit at implementation time. The exact pin means later patches require a deliberate bump, not an automatic update. Node 22 satisfies Next's minimum of 20.9. Keep Webpack build, standalone output, current routes, and authentication unchanged.
- Switch **all three** Docker stages (deps, builder, runner) from `node:20-bookworm-slim` to `node:22-bookworm-slim`, matching CI’s supported Node major. Keep the existing `.env*` Docker context exclusion; also exclude root `benchmark-results/` so private local artifacts aren’t even sent to the builder. Exclude the development-only `scripts/` and `benchmarks/` directories from the Docker build context as well. They are not application inputs; the full-source `checks` CI job still typechecks both. No changes to `tsconfig.json`, the Docker build command, application sources, or Git ignore rules.

## Evidence before implementation

On 2026-11-25: clean `npm ci`, then `npm i --no-save next@16.4.5` in the isolated worktree. `npm ls next` showed the auth package using the same 16.4.5. The **first** `npm run build` after the temporary install succeeded; 84/84 unit tests and lint passed. This was macOS, Node 26.8.1, not Docker or CI; manifests and lockfile were unchanged. An independent temporary manifest/lock copy was needed for a meaningful audit (`--no-save` retains the old lock): its production audit removed the `next` finding. Four moderate findings remained: `glob`, `google-gax`, `minimatch`, `rimraf`. This is not a clean bill of health for all dependencies. No container or CI run is claimed by this probe.

## Implementation checks (2026-11-25)

On macOS under Node 22.23.5 / npm 10.9.11: clean `npm ci`, lint, first production build with no `.next` cache, TypeScript check, 84/84 unit tests and 3/3 production-server integration tests passed. NextAuth resolved with the same Next 16.4.5. Production audit returned the four moderate findings listed above, no Next finding and no high/critical findings. The local standalone server returned HTTP 200 and the expected page text for both `/` and `/practice`. This is not a Docker result: the Actions image job is the container gate. [PR #8](https://github.com/Zihao-Qi/echo-coach/pull/8), [CI run 45719022422](https://github.com/Zihao-Qi/echo-coach/actions/runs/45719022422): checks and Playwright passed. The [image job](https://github.com/Zihao-Qi/echo-coach/actions/runs/45719022422/job/139572340510) passed Docker context inspection, then failed during `RUN npm run build`: `scripts/benchmark-recording.ts` imports `tests/audio/process-memory` and `tests/audio/deadline` while the existing `.dockerignore` excludes `tests`. The runner image was not produced; container Node-version and HTTP checks were not reached. This release-image break predates PR #8: the base branch already shipped the script into the build context but omitted its imported test helpers. The new image job exposed that mismatch. The approved fix keeps both development tooling directories out of the Docker build, rather than weakening typechecking.

Follow-up [CI run 45719607933](https://github.com/Zihao-Qi/echo-coach/actions/runs/45719607933) at `50e9a62`: checks and Playwright passed. The image job passed all context checks, built the image successfully, and passed the Node 22 check (the job proceeded to launch the container). The first HTTP probe failed with `curl: (56) Recv failure: Connection reset by peer`, about 0.12 seconds after `docker run -d` returned and before any Next.js startup output. No HTTP 200/content checks completed. This is consistent with a startup race but does not prove the cause. Stopped that run for approval before changing the probe.

Final [CI run 45720047841](https://github.com/Zihao-Qi/echo-coach/actions/runs/45720047841) at PR head `bea5ea2` (CI merge ref `82a1853`): all three jobs passed, including **38 browser tests**. The [image job](https://github.com/Zihao-Qi/echo-coach/actions/runs/45720047841/job/139575790889) verified the context exclusions and built image `sha256:ae8172d657a9b1b970abc115ff380d4b1b58aab3decf66111e9a03d5acbc5150`, running Node `v22.23.5`. Bounded curl retries covered connection resets during startup (one occurred in this run and recovered on retry). After readiness, `/` returned HTTP 200 with “Good answers are built.” and `/practice` returned HTTP 200 with “Your private practice space.” No assertions were relaxed. No image publication, merge or deployment.
