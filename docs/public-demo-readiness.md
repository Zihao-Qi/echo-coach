# Public demo: try the practice flow without a paid AI call

**Implemented on a review branch; not merged or authorized for launch.** Task A ([Next.js and Node 22](next-patch-node22.md)) landed and passed CI. This branch starts from clean `origin/main` at `42861d6`, without unshipped work from the main checkout. The demo is for showing the practice experience, not for assessing a visitor’s skills or collecting interview answers for research.

## What a visitor gets

The voice and recap release adds the typed mock interview, prerecorded sample audio, a session recap, and optional browser-only recording on starter questions. Public recordings never leave the browser; the editable transcript is a prewritten sample, not recognition of what the visitor said. Audio controls appear only for bundled recordings. `/legacy`, sign-in, and `/api/practice/transcriptions` remain blocked in the public build. These changes supersede the original typed-only preview scope below; the sample-feedback and no-runtime-AI limits still apply.

The next public release adds three new questions, the retry focus cue, and the next-question shortcut to `/practice`, superseding the original no-new-questions scope below. Sample feedback remains clearly labeled. The standalone `/mock-interview` route remains blocked and is not linked from the public home page.

From the home page, a visitor can choose an existing practice question, type a fictional answer, see sample feedback, and try a revision. No account, microphone, payment or provider call is needed. Before submission and alongside the feedback, say in plain language: **“This demo shows sample feedback. It does not assess whether your answer is correct.”** Keep this true on retries and any follow-up. Identify the sender of demo feedback as the demo, not Gemini. Invite visitors to use made-up examples, not personal or confidential details. Use the same clear mock evaluator copy in public and local demos: replace “Configure Gemini for an actual review” and equivalent messages with the sample-feedback notice. This is not a change to the v5 evaluator. Hide all “Original voice demo” links (home and workspace), the recording panel, and sign-in controls. At the reviewed base the README describes legacy/recorded demo features, not the local mock-interview feature; distinguish repository capabilities from those available at the public URL. No public directions should advertise unshipped or disabled features.

History is private to the visitor’s browser session and temporary, not a permanent account record. Tell visitors it may disappear after inactivity or a server restart. A full or expired demo should explain what happened without blaming the answer; never discard an unsubmitted draft on an error or send it automatically.

## Boundaries of the preview

- **Host decision:** Google Cloud Run in the existing owner-designated project, request-based billing, service-level minimum instances **0** and maximum **1**, with traffic directed to one revision (no traffic splitting). Do not set a revision-level warm minimum. Memory storage and the in-process limiter depend on a single serving process; neither is shared across restarts. Scaling to zero avoids paying to keep an instance warm, and a cold start loses history. This is acceptable for this limited demo, not a guarantee of persistent sessions or an absolute resource ceiling.
- Memory storage only. Keep the existing ceilings: 256 sessions, 100 attempts per session, 1,000 attempts overall. Today `get()` and `list()` allocate an empty bucket; listing on page load can consume slots. For the demo allocate a session slot **only on the first accepted attempt write**. Session initialization/cookie issuance, unknown-owner lists (empty), single-record reads (not found) and rejected writes allocate no records, budget entries or capacity slots. Reclaim sessions after 30 minutes without visitor activity, including their attempts and associated counters. Reads needed just to render/poll the UI must not indefinitely renew idle sessions. Do not remove an in-flight evaluation; only skip it until its bounded lease expires. When full, reclaim eligible expired sessions first; if still full, keep active visitors’ data and return a friendly busy response. At the individual cap explain the session limit; don’t promise an immediate retry will free a slot. Session expiry should not bypass an independent traffic limit. Use a single shared in-process limiter at the start of every public practice API request (including access/history reads), before body parsing or storage. Owner decision: admit at most **120 practice API requests per rolling 60 seconds**, shared by all visitors on the single instance. At roughly 2–3 practice API calls per page view that supports about 40–60 page views per minute site-wide (an estimate, not a guaranteed visitor count); one client can exhaust it. The next request returns HTTP 429 with Retry-After. Use server time, not cookies, IPs or forwarded headers; keep at most 120 admission timestamps. Assets are not charged. This is a modest preview traffic ceiling, not denial-of-service protection or a cap on hosting costs; all visitors share it and restarting resets it. No paid gateway, load balancer, or per-IP service in scope.
- Use a dedicated public-demo configuration at build and runtime. Require mock feedback, anonymous demo sessions and memory storage; no provider keys, Google sign-in, database credentials, ambient permissions for paid services, or local-model opt-ins. Disable audio/transcription, legacy pages/APIs (including shared history), and auth endpoints in this profile, including on direct requests. Permit only required app assets and the typed practice path/APIs. An inconsistent or missing required setting must stop the demo from serving, not select a real service. Apart from shared mock evaluator wording, keep other app profiles and the v5 evaluator unchanged.
- Use HTTPS, signed secure session cookies, same-origin writes and non-cacheable private responses. Do not log answers, generated feedback, cookies or request bodies at the app, host, or error reporter. Operational counts of successes, capacity refusals and failures are sufficient. No analytics, permanent storage, new questions, mock-interview module, transcription pilot, research reports or real AI coaching in this release.
- Do not duplicate task A’s dependency or Docker upgrade in B. Preserve its patched runtime and first-build gate; no private environment files in the release image.

**Cost expectation, not a promise of $0.** A linked billing account is required. The [Cloud Run request-based free tier](https://cloud.google.com/run/pricing) is shared per billing account per month: 2 million requests, 180,000 vCPU-seconds and 360,000 GiB-seconds at the reference pricing. Even admitted practice calls alone at 120/minute sustained for 30 days would be about 5.18 million; refused requests and assets can also reach the host. Cloud Build (if used) and Artifact Registry have separate pricing and free tiers. Recheck current pricing and account usage before exposure.

## Build and runtime contract

The dedicated Docker build uses `--build-arg NEXT_PUBLIC_ECHO_PUBLIC_DEMO=true`. It requires explicit runtime `ECHO_PUBLIC_DEMO=true`, `USE_MOCK=true`, `PRACTICE_AUTH_MODE=demo`, `PRACTICE_STORAGE=memory`, `PRACTICE_TRANSCRIPTION_MODE=disabled`, `ALLOW_LOCAL_GEMINI=false`, `ALLOW_LOCAL_TRANSCRIPTION=false`, and `AUTH_URL` set to the exact HTTPS browser origin. Do not supply provider credentials. Default builds preserve the existing non-public paths; enabling the runtime flag on a default build is rejected. Use no `DEMO_SESSION_SECRET` for the preview by default so a process restart invalidates the cookie as well as clearing its saved attempts. Idle entries are reclaimed when the store next handles traffic, not by an idle background task. The existing evaluation lease is two minutes.
